# PUMA Report Engine 功能说明

## 一、系统定位

面向汽车集成标定的报告自动生成程序。
核心能力是：从 PMS 系统拉取项目数据，结合项目填写的基础信息和配置的传感器参数，用模板一键生成标准化报告。


## 二、已完成四种报告

| 报告 | 输入 | 输出 | 适用场景 |
|------|------|------|----------|
| **TCD08** | Word 模板 + 邮件数据 | `.docx/.docm` 校准报告 | 根据 `Calibration Scope` 自动裁剪章节，生成客户审批报告 |
| **TCD09** | Word 模板 + Excel 截图文件 | `.docx` 安装指导手册 | 提取 Excel 截图插入对应章节，生成 Sensor Overview 表格和汽车底图传感器布局 |
| **IAR** | Excel 模板 + PMS 数据 | `.xlsx` 安装评估报告 | 集成 Mounting Checklist、Hammer Test、Sensor Map 等所有公盘链接的评估报告 |
| **Sensor Map** | Excel 模板 + 传感器配置字符串 | `.xlsx` 传感器地图 | 根据配置只保留该项目实际配置的传感器行，删除不需要的传感器和校准列 |

---

所有报告都遵循相同的调用链路：

```
用户在 Workflow 节点页点击报告生成按钮
  → 前端收集 projectId、模板路径、报告类型、传感器配置等参数
  → 请求本机 PUMA_Client (7175)
      ├── TCD08：PUMA_Client 本地解析邮件 → 上传 email_summary JSON
      └── 其它报告：PUMA_Client 读取模板路径
  → PUMA_Client 转发给 PUMA_Server (8086)
      ├── 读取 PMS 数据（API 调用）+ 本地项目数据
      ├── 读取模板文件（从 FolderLinkMapping 配置路径找）
      └── 按报告类型执行对应逻辑，生成结果
  → PUMA_Client 下载结果到本地输出目录
  → 前端提示"生成成功"或"生成失败"
```

## 三、TCD08 校准报告

### 输入

- Word 模板（`.docx` 或 `.docm`，带宏）
- 项目 UUID（关联 PMS 项目）
- 项目填写的 `Calibration Scope`（如 `3*PCS+UFSXY+2*PAS`）
- 项目相关邮件（`.msg` 文件或 email_summary JSON）

### 输出

文件名：`{OEM}_{ProjectName}_Calibration_Report_YYYYMMDD.docx`

### 实际操作流程

#### 1. 填充项目字段

报告中所有 `<PMS.xxx>` 占位符会被替换成实际值，包括：

- `customer`（主机厂，如 Geely）
- `projectName`（项目名称，如 BX11）
- `oem`、`model`、`sop` (SOP Date)
- `peripheral_sensor_configuration` / `internal_sensor_configuration`（外围/惯性传感器配置）
- `MCR_No` (MCR 编号)
- `project_team` / `project_leader`（项目成员）

这些字段优先从 PMS Gateway API 拉取，其次用本地表单填写的数据覆盖，确保本地修改能生效。

#### 2. 填充邮件模拟数据

报告中有 `Email.Send.*` 和 `Email.Approval.*` 占位符，用来模拟审批邮件流转。系统解析项目关联的邮件（发件人、收件人、日期、附件等），自动填充这些占位符。支持两种邮件来源：
- **新方式**：PUMA_Client 本地解析 .msg 文件，上传 JSON 摘要（效率高，不走文件上传）
- **旧方式**：前端上传 .msg 文件或文件夹，服务端解析

#### 3. 根据 Calibration Scope 自动删除章节

报告中有大量章节只适用于部分校准范围，比如：
- `3.2` ~ `3.5`：适用于 FSR 相关校准（如果 Calibration Scope 不包含 `FSR`，自动删除）
- `3.6` ~ `3.7`：适用于 UFS 校准（如果 Calibration Scope 不包含 `UFS`，自动删除）
- `3.8`：适用于 RCS 校准（如果 Calibration Scope 不包含 `RCS`，自动删除）
- `3.9`：适用 PCS 校准（如果 Calibration Scope 不包含 `PCS`，自动删除）

规则在 `generated_catalog_rules.json` 中配置，支持传感器匹配条件（如 `peripheral_has_ufs`、`inertial_has_gyro`）。

#### 4. 处理红色字体段落

模板中用红色字体标注的段落通常是选择性内容，系统会：

- **删除特定段落组**：按章节进入，找到所有红字段落，把相邻"英文+中文"配成一组，根据规则删除指定组。例如某条件不满足时删除第 1、3 组。
- **段落内文本替换**：不改段落位置，只替换段落内的关键词。例如把 `"UFS and RCS"` 替换为 `"UFS"`。

#### 5. 清理后处理

- 删除模板中的说明文字（如"Delete this paragraph"）
- 删除空段落块（没有内容的可选块）
- 将剩余红文字体转为黑色（3.3 和 4.1 章节除外，保留红色）
- 段落编号重排（章节删除后的断号修复）

#### 6. 更新目录

通过 Word COM 打开文档，刷新 Table of Contents（含页码）。因为是 `.docm` 文件，更新后会检测并恢复 `vbaProject.bin` 宏文件，防止宏被破坏。

### 规则配置示例

```jsonc
{
  "condition_refs": {
    "peripheral_has_ufs": "peripheral_sensor_scope 包含 UFS",
    "inertial_has_gyro": "internal_sensor_scope 包含 SMA"
  },
  "calibration_scope": {
    "delete_when_missing": [
      { "missing_value": "FSR", "delete_sections": ["3.2", "3.3", "3.4", "3.5"] },
      { "missing_value": "UFS", "delete_sections": ["3.6", "3.7"] }
    ]
  }
}
```

## 四、TCD09 安装指导报告

### 输入

- Word 模板
- Excel 截图文件（含客户侧截图）
- 项目传感器配置（`internal_sensor_configuration` / `peripheral_sensor_configuration`）

### 输出

文件名：`{OEM}_{ProjectName}_Instruction_Airbag-ECU_and_Sensor_installation_YYYYMMDD.docx`

### 实际操作流程

#### 1. 填充项目基础字段

填充 `customer`、`projectName`、`report_date`（自动生成当前日期，如 `2026.08.17`）、`oem`、`internal_sensor_configuration` 等字段到模板中的 `<PMS.xxx>` 占位符。

#### 2. 从 Excel 提取图片插入 Word

模板中预先放置了图片占位符（如 `<TCD09_IMAGE_3.2>`），系统会：
- 按照 `tcd09_image_rules.json` 配置，查找 Excel 中章节对应的截图
- 提取 Excel 文件中的图片（从 XLSX zip 中读取 Drawing XML）
- 将图片插入到 Word 对应章节位置，按页面宽度自然排版

#### 3. 生成 Sensor Overview 表格

根据传感器配置字符串（如 `3*PCS+UFSXY+2*PAS`），自动填充四列表格：

| Sensor Type | Sensor Location | Sensing Direction | Measurement |
|-------------|-----------------|-------------------|-------------|
| UFS 1 | Centre | Z | ±2g |
| PCS | Outer Level 1 | Z | ±2g |
| PCS | Inner Level 1 | Z | ±2g |
| PAS | Back-Left | Z | ±2g |

- Inertial Sensor 的 Location 固定为 `ECU on tunnel`
- UFS/PAS 的位置根据数量和配置自动计算（LEFT/CENTRE/RIGHT）
- Direction 和 Measurement 优先按精确型号匹配，其次按传感器族匹配，最后使用默认值

#### 4. 生成汽车底图传感器布局

根据传感器配置，在汽车底图上自动生成可编辑的标记（Shape）：
- 每个传感器在底图上生成一个标签和方向标记
- ECU marker 用 `ECU Direction` 控制方向
- UFS marker 用 `UFS direction` 控制方向
- 标记朝汽车外部（前置/后置/左/右）
- 所有 Shape 可在 Word 中拖拽、编辑

模板中底图图片的替代文字（Alternative Text）必须严格设置为 `TCD09_SENSOR_LAYOUT_BASE`，系统会删除旧 Shape 后重新生成，避免重复叠加。

## 五、IAR 安装评估报告

### 输入

- Excel 模板（`.xlsx` 或 `.xlsm`）
- 项目 UUID 或本地项目 ID

### 输出

文件名：`{OEM}_{ProjectName}_Installation_Assessment_Review_YYYYMMDD.xlsx`

### 实际操作流程

#### 1. 构建项目数据字典

从 PMS 拉取项目数据并用本地表单数据覆盖，构建包含 25+ 个字段的字典，供 `<PMS.xxx>` 替换使用，包括：

**项目基本信息：**
```
customer (客户) — Geely
projectName (项目) — BX11
model (车型) — BX11
oem (OEM) — Geely
sop (SOP Date) — 20261231
ab_generation (产品类别) — AB1
region / TargetMarket (市场) — ROW / 欧洲
project_leader (项目负责人) — 张三
MCR_No (MCR 编号) — MCR-L0-001
```

**角色字段（从 TeamMembers 自动解析）：**
```
PJM (Project Manager) — 张三
TPM (Technical Project Manager) — 李四
TPJ (Technical Project Lead) — 王五
PJMEmail / TPMEmail — 各人的 Bosch 邮箱
```

#### 2. 计算 Public Link 路径

根据项目的 Public Link 根路径和 `FolderLinkMapping.json` 配置，自动生成以下路径字段：

```
public_link_root                          → \\bosch.com\dfsrb\...\BX11\
link_hammer_test                          → ...\08_Qualification\Hammer_Test_Report\
link_sensor_map                           → ...\03_Sensor_map\Sensor_Map\
link_mounting_assessment                  → ...\02_Sensor_Mounting\
link_mounting_function_checklist          → ...\02_Sensor_Mounting\Mounting_Function_Checklist\
link_onetcd_tcd09                         → ...\04_Assessment\ONETCD\TCD09\
```

这些路径会替换 Excel 中的 `<PMS.link_xxx>` 占位符。另有别名字段（如 `public_link_hammer_test` → `link_hammer_test`），兼容不同模板的命名约定。

#### 3. 填充 Excel 占位符

Excel 本质是 zip 包，系统修改内部 XML 文件中的占位符：
- `xl/sharedStrings.xml`（共享字符串）
- `xl/worksheets/*.xml`（工作表）
- `xl/drawings/*.xml`（绘图区域）
- `xl/comments*.xml`（批注）

修改过程中所有媒体图片（`.jpg`/`.png`）逐字节保留不变，只替换有 `<PMS.xxx>` 的文本单元格。

## 六、Sensor Map 传感器对应

### 输入

- Excel 模板（`.xlsx`/`.xlsm`）
- `peripheralSensorScope`（如 `3*PCS+UFSXY+2*PAS`）
- `calibrationScope`（如 `Rose1+PitchOver`）

### 输出

文件名：`{OEM}_{ProjectName}_Sensor_Map_YYYYMMDD.xlsx`

### 实际操作流程

#### 1. 解析传感器配置字符串

将用户输入的配置字符串拆分为每个传感器的数量和位置：

| 配置字符串 | 解析结果 |
|-----------|---------|
| `3*PCS` | 3 个 PCS，对称分布在 Level 1 (L/R) 和 Level 0 (C) |
| `UFSXY` | 1 个 UFS，支持 X+Y 轴 |
| `UFSL+UFSC+UFSR` | 3 个 UFS，分别为 LEFT/CENTRE/RIGHT |
| `2*PAS` | 2 个 PAS，Back-Left + Back-Right |

**位置映射规则：**

| 传感器类型 | 拓扑规则 |
|-----------|---------|
| UFS / RCS | `three_position`：1→CENTRE, 2→LEFT+RIGHT, 3+→LEFT+CENTRE+RIGHT |
| PCS | `symmetric_levels`：偶数个为对称层级对 L/R，奇数个多一个中央 C0 |
| PAS | `pillar_pairs`：2→Back-Left+Back-Right, 4→Back-Left+Back-Right+Centre-Left+Centre-Right |
| PPS / PTS | `fixed_positions`：固定位置列表 |

#### 2. 过滤传感器章节

Excel 模板中包含所有传感器的章节，系统只保留该项目实际配置的传感器章节，删除不需要的章节。

例如：
- 配置中有 ` PCS` 和 `PAS`，但没有 `UFS` → 删除 UFS 整个章节
- 配置中有 `UFS`，没有 `PPS` 和 `PTS` → 只保留 UFS，删除 PPS 和 PTS 章节

#### 3. 过滤校准列

根据 `calibrationScope` 判断项目有哪些校准项：
- 配置中包含 `Rose` / `PitchOver` → 保留 ROLL_OVER、PITCHOVER 校准列
- 不包含 `OffZone` → 删除 OFFZONE 校准列
- 不包含 `Pedestrian` → 删除 PEDESTRIAN_PROTECTION 校准列

#### 4. 过滤传感器行

在每个保留的传感器章节内，根据传感器的轴、方位进一步过滤行数据。例如只保留 `Y` 轴的行，删除 `X` 轴的行。
