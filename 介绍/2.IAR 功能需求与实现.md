
## 这项功能做什么

IAR（Installation Assessment Review）功能用于把项目资料填写到既有的 Excel 模板中。

用户在 workflow 中点击 **Fill_IAR** 后，客户端会找到并上传 IAR 模板；服务端根据项目编号获取项目资料，替换模板内的 `<PMS.xxx>` 占位符，并把生成后的一个 Excel 文件返回给客户端。客户端最后将文件保存到项目的 `IAR_Report` 目录。

整个过程可以简单理解为：

```text
选择 Fill_IAR
  → 客户端上传项目编号和 IAR 模板
  → 服务端准备项目资料并填写 Excel
  → 客户端保存生成的 IAR_Report 文件
```

IAR 的输出始终是单个 Excel 文件。例如：

```text
Geely_BX11_Installation_Assessment_Review_20260817.xlsx
```

## 从哪里进入

服务端接口定义在 [PUMA_Server/api/IAR_report.py](../PUMA_Server/api/IAR_report.py)，路由为：

```text
POST /app-puma/report/fillIARDocuments
```

请求中需要上传 `files`，即 IAR Excel 模板。项目标识可以使用下列任一种字段：`projectid`、`projectId`、`project_id`；也可以直接通过 `uuid` 指定 PMS 项目 UUID。

客户端（7175）负责从本机的模板目录读取文件并转发到服务端；服务端只负责生成报告。这样可以避免服务端直接操作用户电脑或公共盘上的文件。

## 模板如何确定

一次上传中可能夹带了多个文件，服务端不会逐个尝试填写，而是只接受配置中指定的 IAR 模板。

模板名称来自 `FolderLinkMapping.json` 中 `TagName` 为 `IAR_Template` 的记录。例如：

```json
{
  "TagName": "IAR_Template",
  "FileKeyWord": "QSCL0415_Installation_Assessment_Review_v3.2.1_auto_label.xlsx"
}
```

服务端会在上传文件中按文件名精确匹配该值（不区分大小写），仅接受 `.xlsx` 或 `.xlsm` 文件。找不到对应文件时接口返回 404，而不是使用其他 Excel 文件继续执行。

配置读取失败时，系统会退回使用默认模板名 `QSCL0415_Installation_Assessment_Review_v3.2.1.xlsx`。

相关逻辑位于 [PUMA_Server/api/IAR_report.py](../PUMA_Server/api/IAR_report.py) 的 `_get_iar_file_keyword_from_mapping()` 和 `_select_iar_upload_file()`。

## 项目资料从哪里来

填充前，服务端会组装一个 profile 字典。模板中的每个 `<PMS.xxx>` 占位符都从这个字典中取值。

首先需要确定 PMS UUID，优先顺序如下：

1. 请求显式传入 `uuid` 时，直接使用它；
2. 否则，根据本地 `projectid` 查询项目记录，并从 `Project.projectInfo.uuid` 取得 UUID；
3. 如果传入的项目标识不是数字，也会将它视作可能的 PMS UUID 进行尝试。

获得 UUID 后，`services/datamerge.py` 中的 `fetch_single_project_details()` 会从 PMS 获取资料，包括基础项目信息、成员信息、OEM、传感器、MCR 和邮件信息等。

远程 PMS 数据并不是唯一来源。本地项目表单中已填写的值会覆盖对应的远程值；如果 PMS 某些字段为空或为 `N/A`，则使用本地数据补足。这保证用户在本地维护的项目资料能够反映到报告中。

常用字段包括：

| 模板占位符 | 含义 | 主要来源 |
|---|---|---|
| `<PMS.customer>` | 客户 | PMS / 本地 Customer |
| `<PMS.projectName>` | 项目名称 | PMS / 本地 Project Name |
| `<PMS.model>` | 车型 | PMS / 本地 Model |
| `<PMS.sop>` | SOP 日期 | PMS / 本地 SOP Date |
| `<PMS.oem>` | OEM | PMS / 本地 OEM |
| `<PMS.region>` | 区域 | PMS / 本地 Region |
| `<PMS.project_leader>` | 项目负责人 | PMS / 本地 Project Leader |
| `<PMS.MCR_No>` | MCR 编号 | PMS / 本地 MCR No. |
| `<PMS.vehicle_variant>` | 车型变体 | PMS |
| `<PMS.plattform>` | 平台 | PMS |
| `<PMS.ab_generation>` | AB 代次 | PMS / 本地 Product Category |
| `<PMS.type>` | 车辆类型 | PMS / 本地 Vehicle Type |

PMS 返回的角色信息有时是类似 `PjM: 张三; TPM: 李四` 的汇总文本。填写前会将其拆开，因此模板可直接使用 `<PMS.PJM>`、`<PMS.TPM>`、`<PMS.PJMEmail>` 等占位符。

此外，服务端会以 Public Link 根目录和 `FolderLinkMapping.json` 的配置为基础，生成报告中需要的公共路径，如：

- `<PMS.public_link_root>`
- `<PMS.link_hammer_test>`
- `<PMS.link_sensor_map>`
- `<PMS.link_mounting_assessment>`
- `<PMS.link_mounting_function_checklist>`
- `<PMS.link_onetcd_tcd09>`

为兼容旧模板，部分旧字段名仍保留别名映射，例如 `public_link_hammer_test` 对应 `link_hammer_test`。报告日期会在生成时自动写为 `YYYY.MM.DD` 格式。

profile 的主入口是 [PUMA_Server/api/IAR_report.py](../PUMA_Server/api/IAR_report.py) 中的 `_build_iar_profile()`；本地字段覆盖和缺失值补齐由 [PUMA_Server/services/datamerge.py](../PUMA_Server/services/datamerge.py) 处理；路径生成由 `_build_iar_public_link_profile()` 和 [PUMA_Server/services/path_resolver.py](../PUMA_Server/services/path_resolver.py) 处理。

## Excel 是怎样填写的

Excel 填写逻辑在 [PUMA_Server/services/IAR_fill.py](../PUMA_Server/services/IAR_fill.py)。

这里没有使用 `openpyxl` 保存工作簿。原因是 IAR 模板可能包含图片、WMF、绘图文本框、页眉或其他 Office 内容；使用常规库重新保存时，这些内容可能被丢失或改变。

实现方式是把 `.xlsx` / `.xlsm` 当作 ZIP 文件处理：只修改含占位符的 XML 文件，其他内容原样复制后重新打包。因此模板中的媒体文件和未知的 Office 内容会被保留。

系统会检查共享字符串、工作表、绘图文本框和批注中的 XML，例如：

- `xl/sharedStrings.xml`
- `xl/worksheets/*.xml`
- `xl/drawings/*.xml`
- `xl/comments*.xml`

占位符可以是 XML 转义后的 `&lt;PMS.customer&gt;`，也可以是原始的 `<PMS.customer>`。两种形式都会被识别。

取值规则如下：

- `<PMS.customer>` 直接读取 `profile["customer"]`；
- 组合占位符可用短横线连接，例如 `<PMS.customer-project>` 会组合 `customer` 和 `project` 的值；
- 找不到对应字段时写入 `N/A`；
- `None` 同样写为 `N/A`；列表以逗号连接，字典以 `键: 值` 的形式连接。

关键函数为 `fill_excel_by_placeholders()`、`_replace_placeholders_in_xml_text()`、`_resolve_placeholder_value()` 和 `_stringify_value()`。

## 返回文件与命名规则

报告文件名按以下格式生成：

```text
{customer}_{projectName}_Installation_Assessment_Review_{YYYYMMDD}.xlsx
```

其中客户名称取自 `profile["customer"]`，项目名称优先取 `projectName`，没有时使用 `project`。文件名中的 Windows 非法字符会替换为下划线。

服务端通过下载响应返回文件，并附带以下响应头：

- `Content-Disposition`：浏览器或客户端保存时使用的文件名；
- `X-IAR-Template-File`：本次匹配到的模板文件名；
- `X-IAR-Output-Mode: single-excel`：说明返回的是单个 Excel 文件。

`.xlsx` 和 `.xlsm` 会使用各自对应的 Excel MIME 类型。

相关函数在 [PUMA_Server/api/IAR_report.py](../PUMA_Server/api/IAR_report.py)：`_output_filename()`、`_sanitize_filename_part()` 与 `_media_type_for_excel()`。

## 排查时优先看哪里

| 现象 | 优先检查 |
|---|---|
| 提示找不到模板 | `FolderLinkMapping.json` 的 `IAR_Template` 名称，以及客户端实际上传的文件名 |
| 基础信息不正确或为空 | PMS UUID 是否正确；本地项目表单的覆盖值；`fetch_single_project_details()` 的结果 |
| Public Link 路径不正确 | `FolderLinkMapping.json` 的路径配置和 `path_resolver.py` 的解析结果 |
| 模板中仍有 `<PMS.xxx>` | 占位符是否位于受支持的 XML 内容中；profile 是否有同名字段 |
| 图片或格式异常 | 确认模板仍以原始 Excel 文件上传，且填写流程没有改用会重新保存工作簿的库 |
