# 开发过程提到的问题与解决思路记录

1. **TCD08 邮件大附件传输**  
   问题：将 `.msg` 及其中 ZIP 附件从 Client 上传到 Server，可能被 nginx/gateway 以请求体过大拦截，导致报告生成中断。  
   解决思路：将邮件解析前移到 7175 Client；Client 只读取本地 `Customer_Approval_Email` 目录，解析 ZIP 名称、Excel 名称、发送/回复信息等摘要，再将 `email_summary` JSON 发给 8086。这样 Server 不再接收邮件和 ZIP 文件本体。  
   关键位置：`PUMA_Client/local_email_parser.py`、`PUMA_Client/client.py`、`PUMA_Server/services/tcd08/report.py`。

2. **本地 C 盘目录操作与 Server 职责冲突**  
   问题：8086 Server 无法可靠操作每个用户电脑上的 C 盘文件夹。  
   解决思路：前端把项目、用户、部门、CalibrationID 等信息交给 8086 计算路径；7175 Client 在本机执行 `copy`、`mkdir`、`rename` 和打开目录。完成结果再返回前端。  
   关键位置：`PUMA_Server/api/project.py`、`PUMA_Server/services/path_resolver.py`、`PUMA_Client/client.py`。

3. **本地目录模板和固定目录规则分散**  
   问题：复制、创建、重命名时容易找错 `40.Application`、`C.Calibration` 或参数目录。  
   解决思路：将本地根目录、40.Application 模板源路径、`C.Calibration` 名称、参数结构模板名和默认 CalibrationID 集中定义在 Client；复制和重命名逻辑统一读取这些常量。  
   关键位置：`PUMA_Client/client.py` 中的 `BASE_DIR`、`SOURCE_CALIBRATION_TEMPLATE`、`CALIBRATION_FOLDER_NAME`、`DEFAULT_CALIBRATION_IDS`。

4. **获取Calibration树的名称**  
   解决思路：按照最后的下划线来决定这个id名。
   关键位置：split函数能够进行摘取。

4. **删除Node**  
   解决思路：制作删除节点按钮。实现从项目数据库中删除这一条
   关键位置：同时，不会删除公盘上面的位置，仅作树结构的调整。

4. **Todo的功能需要设计**  
   解决思路：提供和proj类似的几个按钮，作为完成或ongoing
   关键位置：仅需要gate的编写。

4. **工作流配置职责混乱**  
   解决思路：`unified.json` 仅维护任务树；`WorkFlow.json` 维护节点 IPO 和操作；`FolderLinkMapping.json` 维护标签到文件位置的映射。新增节点时按这三层分别配置，避免把路径和业务操作写死在页面。  
   关键位置：`DB/templates/unified.json`、`DB/templates/WorkFlow.json`、`DB/templates/FolderLinkMapping.json`。

4. **Logo 占位符无法识别**  
   解决思路：统一 Word 替代文字与占位符名称，修正文本匹配规则；Logo 路径由配置层提供，替换函数只负责查找和写入图片。  
   关键位置：`datamerge` 下的文档替换逻辑、`PUMA_Server/utils/path_config.py`。

4. **AddNode呢**  
   再重构一下Caliid的设计。



6. **Word 表格换行、字体和分页不符合模板**  
   解决思路：写入时沿用原单元格/段落样式，避免覆盖字体；根据内容插入换行，并将重要表格行设置为不跨页拆分。  
   关键位置：`PUMA_Server/services/word/`、`datamerge/custom_python_docx/`。

7. **Word 目录无法自动更新**  
   解决思路：在具备 Word 的环境执行 TOC 刷新；Windows COM 调用放到已初始化 COM 的线程中，避免目录不刷新或线程异常。并发生成时应对同一文件加锁。  
   关键位置：文档 TOC 处理代码、`PUMA_Server/services/word/`。

8. **绝对输出路径不能正确使用**  
   解决思路：映射配置存在 `AbsolutePath` 时直接返回它；只有没有绝对路径时才使用项目根目录加 `RelativePath`。  
   关键位置：`DB/templates/FolderLinkMapping.json`、`PUMA_Server/services/path_resolver.py` 的 `resolve_path()`。

9. **路径解析时找不到项目文件夹**  
   解决思路：后端根据标签、项目配置、任务 ID 和映射规则统一计算路径；对缺失 Local/Public Link、无映射项、任务层级不匹配等情况返回可读的 `400` 错误。  
   关键位置：`PUMA_Server/api/project.py` 的 `get_path()`、`PUMA_Server/services/path_resolver.py`。

10. **服务器直接处理用户 C 盘文件不可靠**  
    解决思路：8086 只做路径解析、工作流和报告编排；7175 处理本地文件系统。这样部署在服务器的程序不会误以为自己能访问用户的本地路径。  
    关键位置：`PUMA_Server/api/project.py`、`PUMA_Client/client.py`、`app-pms-project/src/context/AppContext.js`。

11. **40.Application 目录缺失或结构不一致**  
    解决思路：由 Client 从统一模板复制 `40.Application`，并按默认节点名创建对应标定目录；不在 Server 中直接写用户 C 盘。  
    关键位置：`PUMA_Client/client.py` 的复制/创建目录接口。

12. **更新项目信息时误触发完整文件夹复制**  
    解决思路：项目信息保存只调用创建所需目录的逻辑，不复用完整模板复制；目前限制创建 A. Vehicle integration 下的 01–07 目录。  
    关键位置：`app-pms-project/src/context/AppContext.js`、`PUMA_Client/client.py` 的 `createFolders`。

13. **任务输入输出位置不统一**  
    解决思路：`RelativePath`、`AbsolutePath`、`StorageType` 和 `FileKeyWord` 成为唯一的位置规则；报告接口只使用已解析的实际输入和输出路径。  
    关键位置：`DB/templates/FolderLinkMapping.json`、`PUMA_Server/services/path_resolver.py`。

14. **Local Link 与 Public Link 填为同一 C 盘路径后，Sensor Map 等操作异常**  
    解决思路：这是存储位置配置与业务语义耦合的问题。操作前需校验实际路径、存储类型和所需文件；业务代码不能仅因参数名是 Local/Public 就假定目录内容正确。  
    关键位置：`PUMA_Server/services/path_resolver.py`、`app-pms-project/src/components/pages/TaskDetailPage/index.jsx`。

15. **工作流子节点的文件操作入口不明显**  
    解决思路：在输入/输出项悬浮时展示 Local、Public、SharePoint 图标，并将标签和任务 ID 传入统一的路径请求。  
    关键位置：`app-pms-project/src/components/pages/TaskDetailPage/WorkFlow/index.jsx`、`SidebarRight/index.jsx`。

16. **执行报告前用户遗漏必需输入文件**  
    解决思路：在工作流节点添加 `preflight` 配置；执行前解析并打开目标目录，再弹窗要求用户确认文件已准备好。  
    关键位置：`DB/templates/WorkFlow.json`、`app-pms-project/src/components/pages/TaskDetailPage/index.jsx` 的 `runPreflight()`。

17. **TCD08 和 TCD09 的前置检查不同**  
    解决思路：每个节点各自配置输入标签、检查文案和报告接口，前端使用通用 preflight 执行器，不把某份报告的规则硬编码为全局逻辑。  
    关键位置：`DB/templates/WorkFlow.json`、`TaskDetailPage/index.jsx`。

18. **删除工作流节点后误操作无法恢复**  
    解决思路：前端内存保存最近一次删除前的完整 workflow；服务端成功保存后给出短时间 Undo，恢复节点、子节点、ID、状态和 `taskDetails`。刷新、切换项目和后续修改时清除记录。  
    关键位置：`app-pms-project/src/components/Menu/Progress/index.jsx`。

19. **保存后页面数据没有及时刷新**  
    解决思路：成功保存后由 Server 发布 SSE 事件，前端按事件重新加载项目、工作流或 Todo；失败时保留或恢复提交前状态。  
    关键位置：`PUMA_Server/api/sse.py`、各 API 的 `event_bus.publish()`、前端 `AppContext.js`。

20. **IAR 原先依赖旧端口服务**  
    解决思路：将 IAR 填写迁移到 PUMA Server；工作流用 `Fill_IAR` 配置调用新的报告接口，统一由 Server 处理占位符和输出。  
    关键位置：`DB/templates/WorkFlow.json`、`PUMA_Server` 的 IAR 报告接口和服务。

21. **IAR 报告需要填写 Hammer Test 等项目链接**  
    解决思路：占位符先映射为业务标签，再从 FolderLinkMapping 和项目根目录计算链接，最后写入 Word；不把网络路径写死在模板处理代码中。  
    关键位置：IAR 报告服务、`DB/templates/FolderLinkMapping.json`。

22. **IAR 日期或封面信息缺失**  
    解决思路：补充项目字段；封面项目名从数据库项目记录读取，日期等信息集中在报告生成服务中填写。  
    关键位置：项目模型与 IAR 报告服务。

23. **报告输出文件命名不统一**  
    解决思路：由报告接口集中生成文件名，例如“项目名_Calibration_Report_日期.docm”，避免前端和不同报告服务各自命名。  
    关键位置：`PUMA_Server/services/tcd08/report.py` 及其他报告服务。

24. **封面后分页符、红蓝提示文字格式异常**  
    解决思路：在文档指令层为特殊句子单独设置样式和分页符，而不是交给通用字符串替换，防止格式丢失。  
    关键位置：`PUMA_Server/services/word/`、TCD08 报告处理逻辑。

25. **TCD08 第七章无数据时仍显示不适用内容**  
    解决思路：根据缺失数据名单控制 `optional_blocks`；无数据时写入 NA 或删除对应段落，避免保留误导性默认内容。  
    关键位置：`PUMA_Server/services/tcd08/report.py`。

26. **标定系数文件名解析不稳定**  
    解决思路：按第一个下划线取关键标识，并统一 `split`/`rsplit` 规则，避免项目名中包含下划线时被错误切分。  
    关键位置：`PUMA_Server/services/tcd08/report.py`。

27. **TCD09 的 Word、Excel 和输出文件混在一起**  
    解决思路：Excel 仅作为图片和表格数据源，Word 模板独立处理；输入输出目录均由映射配置和报告接口统一解析。  
    关键位置：`PUMA_Server/api/TCD09report.py`、`PUMA_Server/services/tcd09/`、`FolderLinkMapping.json`。

28. **Excel 图片无法按章节准确写入 Word**  
    解决思路：通过 `start_label` 和可选 `end_label` 识别 Excel 章节范围；按原比例将图片连续插入段落，让 Word 自然换行。  
    关键位置：`PUMA_Server/config/tcd09_image_rules.json`、`PUMA_Server/services/tcd09/excel_images.py`。

29. **图片来源 Excel 文件选择错误或不唯一**  
    解决思路：先按唯一 Excel 匹配；仍不唯一时再按“图片”等关键字筛选，并在无法确定时返回明确提示而不是随机选文件。  
    关键位置：TCD09 报告服务中的输入文件筛选逻辑。

30. **传感器概览表无法识别复杂传感器写法**  
    解决思路：支持 `+`、`_`、`-`、`3*UFS`、`UFSL+UFSC+UFSR`、`4*PAS` 等表达式，解析后自动填写型号和安装位置；Inertial Sensor 固定为 ECU on tunnel。  
    关键位置：`PUMA_Server/services/tcd09/` 的传感器解析/表格生成逻辑。

31. **车辆传感器布局图不能随配置自动变化**  
    解决思路：用 Word 替代文字定位车辆底图，动态生成可编辑 Shape；ECU、UFS 和外围传感器按各自数量、位置和朝向规则绘制。  
    关键位置：`PUMA_Server/services/tcd09/sensor_layout_model.py`。

32. **UFS 和 ECU 方向配置不一致**  
    解决思路：前端提供 UFS `normal/reverse` 和 ECU `forward/backward/left/right`；报告服务将这些枚举映射到布局图中的坐标和旋转规则。  
    关键位置：Sensor Map/TCD09 前端字段和 `sensor_layout_model.py`。

33. **RCS 文字和目录内容残留**  
    解决思路：按章节规则保留或删除红字；内容处理完成后再调用已修正的 TOC 更新流程，防止目录仍显示已删除标题。  
    关键位置：TCD09 规则配置、Word 指令处理和 TOC 更新服务。

34. **本地邮件解析出现文件过大和转发邮件读取失败**  
    解决思路：使用 `TeamMembers.json` 区分内部人员，交给本地解析器提取发件人、姓名和附件名称；只上传摘要，避免大附件进入 HTTP 请求。  
    关键位置：`PUMA_Client/local_email_parser.py`、`DB/templates/TeamMembers.json`。

35. **用户账号、显示名和权限判断不一致**  
    解决思路：集中使用 `TeamMembers.json` 的账号—姓名映射；权限、人员选择和邮件解析均使用同一映射，避免直接混用账号和姓名。  
    关键位置：`PUMA_Server/api/project.py`、`PUMA_Server/api/todo_v2.py`、`DB/templates/TeamMembers.json`。

36. **Client 版本过旧导致本地能力不一致**  
    解决思路：前端下载并使用最新版 Client；启动时确认 7175 服务正常，新增本地接口时同步维护 Client 发布版本。  
    关键位置：`PUMA_Client/README.md`、前端 Client 下载/调用逻辑。

37. **公盘模板或项目目录无法访问**  
    解决思路：部署和使用前确认 N 盘/DFS 权限；路径解析和文件操作失败时展示可理解的权限或路径提示，避免只显示通用错误。  
    关键位置：`PUMA_Server/utils/path_config.py`、`PUMA_Client/client.py`。

38. **报告和文件操作功能增加后代码耦合变高**  
    解决思路：持续按配置、路径解析、文件处理、文档生成、图片处理和接口编排分层；新报告优先复用 `services/word`、路径解析器和配置文件。  
    关键位置：`PUMA_Server/services/`、`PUMA_Server/config/`、`DB/templates/`。
