# TCD09 功能实现说明

## 1. 文档目的

三个主要功能是：

1. Excel 章节图片自动提取并插入 Word。
2. Sensor Overview 四列表格自动生成。
3. 汽车俯视图传感器 Shape 自动生成。

此外，普通 `<PMS.xxx>` 文本占位符也会在统一流程中完成替换。

## 2. 总体入口

后端入口位于 `PUMA_Server/api/TCD09_report.py`。
接口为 `POST /report/fillTCD09Report`，核心函数是 `fill_tcd09_report()`。
接口接收项目编号、Word 模板和 Excel 文件。

完整处理顺序如下：

1. `select_tcd09_template_file()` 选择 TCD09 Word 模板。
2. `select_tcd09_ufs_excel_file()` 选择 TCD09 Excel 文件。
3. `_build_tcd09_profile()` 汇总远程 PMS 和本地项目数据。
4. `insert_excel_section_images()` 将 Excel 图片插入 Word。
5. `fill_tcd09_sensor_type_rows()` 生成 Sensor Overview 表格行。
6. `fill_docx_by_placeholders()` 替换普通 `<PMS.xxx>` 占位符。
7. `insert_tcd09_sensor_layout_shapes()` 最后创建可编辑 Word Shape。
8. 通过 `StreamingResponse` 返回最终 DOCX 文件。

Word COM 必须最后执行，因为后续再次使用 python-docx 保存文档，可能破坏或改变 Shape。

## 3. 项目资料与普通占位符

`_build_tcd09_profile()` 负责生成统一的 `profile` 字典。
它优先读取项目关联的 PMS UUID，并请求远程 PMS 项目详情。
随后使用本地保存的 `projectInfo` 覆盖远程数据。
这样前端最新保存的传感器配置和项目字段可以进入报告。

常用字段包括：
·
- `customer`
- `projectName`
- `internal_sensor_configuration`
- `peripheral_sensor_configuration`
- `ECU Direction`
- `UFS direction`
- `report_date`

`report_date` 在生成报告时自动设置为当前日期，格式为 `YYYY.MM.DD`。
因此 Word 中的 `<PMS.report_date>` 可以直接被替换。

普通占位符由 `services/datamerge.py` 中的 `fill_docx_by_placeholders()` 处理。
TCD09 调用时关闭邮件占位符逻辑，避免触发 TCD08 专用邮件处理。

## 4. 功能一：Excel 图片自动填写
以一张底片图片，《替换文字》叫TCD09_SENSOR_LAYOUT_BASE，在他的左上角开始定位绘制矩形。
实现文件为 `PUMA_Server/services/tcd09/excel_images.py`。
规则文件为 `PUMA_Server/config/tcd09_image_rules.json`。

每条图片规则主要包含：

- `placeholder`：Word 图片占位符。
- `sheet_name`：Excel Sheet 名称。
- `start_label`：章节起始标题。
- `end_label`：可选的章节结束标题。
- `customer_start_column`：客户侧区域起始列。
- `image_width_inches`：单张图片最大显示宽度。

`load_tcd09_image_rules()` 校验 JSON 结构和必要字段。
`_resolve_section_window()` 根据标题确定章节起止行。
起始标题所在行包含在章节内，结束标题所在行不包含在章节内。
未配置 `end_label` 时，章节延伸到 Sheet 末尾。

`_iter_images_for_window()` 直接读取 XLSX/XLSM 压缩包中的 Drawing XML。
它根据图片锚点行列筛选客户侧章节范围内的图片。
图片按行、列和媒体路径排序，保证插入顺序稳定。

`_materialize_docx_image()` 将 Excel 媒体写入临时目录。
普通图片直接使用，EMF 图片通过 PowerShell 和 System.Drawing 转为 PNG。

`insert_excel_section_images()` 查找 Word 中完全匹配的占位符段落。
找到图片后清空占位符，并把所有图片作为 InlineShape 连续加入同一段落。
图片之间只加入普通空格，不主动加入换行符。
因此 Word 会根据页面剩余宽度自然换行，而不是每张图片独占一行。
插入时只指定宽度，不指定高度，从而保持图片原始比例。

## 5. 功能二：Sensor Overview 自动填写

主要实现文件为 `PUMA_Server/services/tcd09/sensor_overview.py`。
规则文件为 `PUMA_Server/config/tcd09_sensor_overview_rules.json`。
传感器解析逻辑位于 `sensor_parser.py`，公共模型位于 `sensor_models.py`。

`sensor_parser.py` 支持：

- `+`、`_`、`-`、逗号、分号等连接符。
- `3*UFS`、`4*PAS`、`4*PPS` 等数量写法。
- `UFSL+UFSC+UFSR` 等显式位置写法。
- 型号、传感器族、数量和位置后缀归一化。

`merge_sensor_entries()` 把输入转换为去重后的 `SensorEntry` 列表。
`SensorEntry` 保存传感器族、显示型号、数量、位置和是否为惯性传感器。

`build_sensor_overview_rows()` 为每个传感器生成四列：

1. Sensor Type：传感器型号。
2. Sensor Location：安装位置。
3. Sensing Direction：感知方向。
4. Measurement：测量对象。

Inertial Sensor 的安装位置固定为 `ECU on tunnel`。
UFS、PAS、PPS、RCS、PCS、PTS 的位置根据数量或显式位置计算。
第三、四列优先按精确型号匹配规则，其次按传感器族匹配，最后使用默认值。

Word 模板行必须在同一行前四列放置以下占位符：

- `<TCD09_SENSOR_TYPE_ROWS>`
- `<TCD09_SENSOR_LOCATION_ROWS>`
- `<TCD09_SENSOR_DIRECTION_ROWS>`
- `<TCD09_SENSOR_MEASUREMENT_ROWS>`

`_find_sensor_template_rows()` 查找该模板行。
`_expand_template_row()` 按传感器数量复制整行并替换四列内容。
复制 XML 整行可以保留边框、宽度、高度和原有格式。
完成后原始占位符模板行会被删除。

## 6. 功能三：汽车底图可编辑 Shape

布局数据由 `PUMA_Server/services/tcd09/sensor_layout_model.py` 生成。
Word 操作由 `PUMA_Server/services/tcd09/sensor_layout_word.py` 完成。
布局规则位于 `PUMA_Server/config/tcd09_sensor_layout_rules.json`。

`build_sensor_layout_model()` 将传感器配置转换为 slot、标签和 marker 数据。
ECU marker 使用 `ECU Direction` 控制方向。
UFS marker 使用 `UFS direction` 控制方向。
其他外围传感器依据 slot 配置固定朝汽车外部。

`insert_tcd09_sensor_layout_shapes()` 使用 Windows Word COM 操作文档。
`_find_base_picture()` 查找替代文字严格等于 `TCD09_SENSOR_LAYOUT_BASE` 的《浮动图片》。
底图必须唯一、位于正文 Story 中，并且不能是 InlineShape。

生成前，`_delete_old_generated_shapes()` 删除指定前缀的旧 Shape。
这样重复执行不会不断叠加相同图形。
`
`_create_label_shape()` 按底图宽高比例计算标签矩形的位置和尺寸。
`_create_marker_shape()` 根据标签边缘、方向和 marker 样式计算标记位置。
所有生成对象都是普通 Word Shape，可以在 Word 中拖拽和编辑。

布局 JSON 控制 slot 坐标、尺寸、旋转、颜色、字体和 marker 朝向。
因此调整视觉布局通常只需修改 JSON，而不需要修改 Python 代码。

该功能依赖 Windows、Microsoft Word 和 `pywin32`。
函数会在读取输出后关闭 Document、退出 Word 并释放 COM，再清理临时目录。
这可以避免临时 DOCX 被 Word 锁定。

## 7. 当前模块职责

- `report.py`：根据映射和文件名选择上传的 Word、Excel 文件。
- `excel_images.py`：解析 Excel Drawing 并插入章节图片。
- `sensor_models.py`：定义公共传感器模型和位置常量。
- `sensor_parser.py`：解析和归一化前端传感器字符串。
- `sensor_overview.py`：生成四列数据并填写 Word 表格。
- `sensor_layout_model.py`：生成底图 slot、标签和 marker 模型。
- `sensor_layout_word.py`：通过 Word COM 创建和保存 Shape。
- `TCD09_report.py`：串联所有步骤并返回最终文档。

## 8. 修改功能时的快速定位

修改图片章节或占位符：调整 `tcd09_image_rules.json`。
修改 Overview 方向或测量对象：调整 `tcd09_sensor_overview_rules.json`。
修改传感器默认数量或位置：检查 `sensormap_sensor_rules.json`。
修改底图标签位置、颜色或方向：调整 `tcd09_sensor_layout_rules.json`。
新增传感器字符串语法：修改 `sensor_parser.py`。
修改 Word 表格生成：修改 `sensor_overview.py`。
修改 Shape 创建和几何计算：修改 `sensor_layout_word.py`。
修改总体执行顺序或 profile 字段：修改 `api/TCD09_report.py`。

## 9. 模板使用要求

Word 模板必须包含四列表格占位符、所需图片占位符以及标记后的汽车底图。
图片占位符目前应位于普通正文段落中，并且段落文本应与占位符完全匹配。
汽车底图替代文字必须严格设置为 `TCD09_SENSOR_LAYOUT_BASE`。
Excel 的 Sheet 名、章节标题和客户侧列必须与图片规则一致。
满足这些条件后，前端执行 TCD09 工作流即可生成完整报告。
