## 2. PUMA Server（后端 FastAPI）

启动入口：`PUMA_Server/main.py`，创建 FastAPI 应用，`root_path="/app-puma"` 所以所有接口最终挂载在 `/app-puma/...` 下。

后端代码分为几个大模块：

### 2.1 项目 / Todo 管理

核心接口在 `api/project.py` 和 `api/todo_v2.py`，覆盖项目 CRUD、Workflow 更新、Todo 增删改查。权限模型基于 Owner/Proxies + TeamMembers.json 校验。


### 2.2 报告生成模块

这是系统最核心的部分。四个报告共享同一套调用模式：前端 → Client → Server → 生成文档。

**`api/report.py`** — TCD08 和 Sensor Map 的入口：
- TCD08：接收 UUID + ProjectId + 邮件数据(email_summary JSON) + 模板路径，调用 `services/tcd08/report.py` 执行占位符替换、章节删除、红字段落处理、更新目录
- Sensor Map：解析传感器配置字符串，调用 `services/sensormap/service.py` 生成过滤后的 Excel

**`api/IAR_report.py`** — IAR 报告的入口，独立大文件（近 700 行），处理模板选择、PMS/本地数据合并、Public Link 路径计算

**`api/TCD09_report.py`** — TCD09 报告的入口，调用 `services/tcd09/` 目录下的模块完成 Excel 图片提取、Sensor Overview 表格生成、汽车底图 Shape 创建

**报告共用层：**
- `services/datamerge.py` — PMS 数据拉取（并行请求 3 个 API 端点）、`<PMS.xxx>` 占位符替换（正文/表格/表头/页脚）、邮件解析（两种来源：JSON 摘要 vs 上传 .msg）
- `services/IAR_fill.py` — IAR 专属的 Excel 占位符填充（zip 解压 → 改 XML → 重新打包）
- `services/word/` — TCD08 的 Word 处理模块：章节删除、红字段落删除、段落内改写、目录更新、宏保护、提示语删除、红字转黑字
- `services/tcd09/` — TCD09 专属模块：图片提取、传感器解析、Overview 表格、底图 Shape
- `services/sensormap/` — Sensor Map 专属模块：传感器解析、拓扑映射、Excel COM 编辑

所有报告文件路径查找统一走 `services/path_resolver.py` + `FolderLinkMapping.json`。

### 2.3 其他接口

- `api/pms.py` — PMS 系统集成（刷新/预览/同步）
- `api/templates.py` — 从 DB 读取模板 JSON 返回给前端
- `api/sse_stream.py` / `api/sse.py` — SSE 事件流和 EventBus 实现
- `api/download.py` — 提供 `Client.exe` 下载
- `crud/` 和 `models/` 和 `schemas/` — SQLAlchemy ORM 层、Pydantic 数据校验

## 3. PUMA Client（本地桥接服务）

`PUMA_Client/client.py` 是一个本地 FastAPI 进程（port 7175），常驻系统托盘。浏览器无法完成的本机操作都由它代理执行。

**核心接口：**

| 接口 | 说明 |
|------|------|
| `/userinfo` | 获取本机操作系统用户名，用于前端鉴权 |
| `/openPath` | 用默认程序打开文件夹或文件 |
| `/open/link` | 用浏览器打开 URL |
| `/PMSInfo/{uuid}` | 桥接远程 PMS API：发送 UUID → 获取 protobuf 二进制 → 用 dataprovider_pb2 解析 → 转为 JSON 给前端 |
| `/copy-folder` | 复制本地目录 |
| `/copyApplicationTemplate` | 复制 40.Application 模板结构 |
| `/saveReport` | 接收报告文件并保存到本地指定路径 |

**特殊能力：**
- 调用微软 COM 组件解析本地 .msg 邮件文件，提取发件人/收件人/日期/附件，生成 JSON 摘要（仅 TCD08 需要）
- 被打包为 `Client.exe` 分发：`PUMA_Server/api/download.py` → `DB/downloads/Client.exe`

## 4. 两个前端

两个前端都是 React + CRA 项目，通过 `AppContext.js` 统一管理 API 调用和全局状态。

### 4.1 Gate 前端

`app-pms-gate/src/App.jsx` — 双面板 Splitter 布局：

| 左侧面板 | 右侧面板 |
|----------|----------|
| SearchBar（快捷链接搜索，来自 StandardLinks.json） | ProjectSummary（项目列表、统计图、拖拽排序） |
| ToDoList（Todo 增删改查、进度追踪） | SSE 实时刷新：ProjectUpdated / TodoDeleted 等事件 |

登录逻辑：访问 `http://127.0.0.1:7175/userinfo` 获取本机用户，作为当前登录身份。

### 4.2 Project 前端

`app-pms-project/src/App.jsx` — HashRouter，两种页面：

| 路由 | 功能 |
|------|------|
| `/edit` | 项目资料编辑页：二维表单填写、Owner/Proxies 选择、PMS 导入（获取 UUID → 调 Client → 调远程 PMS → 映射 14 个字段）、Auto Fill Links |
| `/task/:projectId/:taskId` | 任务详情页：Workflow 节点输入/输出文件夹、Operation 按钮一键生成报告、任务状态变更（Pending/Ongoing/Done/Decline）、评论 |

左侧固定 `Menu` 面板：`ProjectInfo`（项目卡片 + 完成度进度条）+ `Progress`（Workflow 树，展开折叠、复制/删除节点、新增 CalibrationID）

Operation 按钮（如 Fill TCD08、Fill IAR）触发流程：前端收集参数 → 调本端 7175 → Client 转发 → 后端 8086 生成 → Client 下载保存 → 前端提示成功。

## 5. 完整数据链路示例（以 TCD08 为例）

```
用户在 Project 端 Workflow 树点击节点 → 填写参数（UUID、Calibration Scope）→ 点击 "Fill TCD08"
  ↓
前端调 PUMA Client(7175) → Client 本地解析邮件 → 生成 email_summary JSON
  ↓
前端把 email_summary + 项目参数发给后端 8086 → POST /report/fillTCD08Report
  ↓
后端：读取 PMS 数据 (3 个并行 API) + 本地项目数据 (SQLite)
     → 填充 Word 模板中的 <PMS.xxx> 占位符
     → 根据 generated_catalog_rules.json 计算删除计划
     → 执行章节删除 + 红字段落处理 + 目录更新
     → 返回 .docx/.docm 文件
  ↓
Client(7175) 接收文件 → 保存到 TCD08_Report 目录
  ↓
前端 SSE 推送 ProjectUpdated → ProjectList 页面自动刷新
```
