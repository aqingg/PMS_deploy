# TCD08 功能需求与实现

## 1. 文档目的

本文介绍 TCD08 校准报告生成的完整功能、代码结构和运行流程。TCD08 是本系统最复杂的报告功能，核心逻辑是：读取 Word 模板 → 替换占位符 → 根据规则删除/改写内容 → 产出标准化报告。

## 2. 功能一：占位符填写

报告生成的第一步是替换模板中的占位符。

替换范围覆盖 Word 文档的正文、表格、表头、页脚。所有 `<PMS.xxx>` 格式的占位符都会被 `profile_dict` 中的数据填充，例如 `<PMS.customer>` → `Geely`、`<PMS.project>` → `BX11`。

除了项目基础字段，还包括两类特殊占位符：
- `<PMS.logo>`：替换为公司 Logo 图片
- `Email.Send.*` / `Email.Approval.*`：填充邮件模拟数据

邮件数据支持两种来源（优先级从高到低）：
1. `email_summary` JSON（由 PUMA_Client 本地解析 .msg 文件后生成，新方式）
2. 上传的 .msg 文件或文件夹（旧方式，兼容）

## 3. 功能二：规则驱动的章节删除与段落处理

第二步是根据 `generated_catalog_rules.json` 计算"要删什么、要改什么"，得到三部分删除/改写计划：

**3a. 章节删除**（按 Calibration Scope 决定删除哪些大节）
- 解析 `Calibration Scope` 字段值（如 `3*PCS+UFSXY+2*PAS`）
- 对照规则文件中的 `delete_when_missing` 列表，判断哪些章节应删除
- 例如：当 Calibration Scope 不包含 `FSR` 时，删除 `3.2`、`3.3`、`3.4`、`3.5` 章节
- 删除方式：扫描 `document.xml` 找到章节标题，从该标题删到下一个同级或上级标题之前

**3b. 红色段落组删除**（按规则删除章节内的红字段落）
- 进入指定章节，找到所有红色字体段落
- 把紧挨着的"英文 + 中文"合成一组，按出现顺序编号为第1组、第2组
- 根据规则决定删除哪些组（如 `delete_groups: [1, 3]`）
- 判断条件支持传感器匹配（如 `peripheral_has_ufs`、`inertial_has_gyro`）和字段值匹配

**3c. 红色段落内局部改写**（不改段落位置，只替换词）
- 在指定红色段落组内执行多组旧词 → 新词替换
- 例如：把 `"UFS and RCS"` 替换为 `"UFS"`
- 替换逻辑处理 `<w:t>` 跨节点情况，确保准确写入

## 4. 功能三：文档处理

第三步是对修改后的 Word 文档进行收尾处理：

**4a. 删除空邮件模拟块**
- 检测并删除空的"Email simulation"可选块（standard/defect/specific XLSX 文件对应的段落）

**4b. 删除模板维护提示语**
- 根据配置开关 `REMOVE_TEMPLATE_INSTRUCTIONS_ENABLED`，删除模板中的说明文字（如"Delete this paragraph"）

**4c. 红色字体转黑色**
- 根据配置开关 `REPLACE_RED_FONT_WITH_BLACK_ENABLED`，将剩余红字段落改为黑色
- 白名单例外：`3.3`、`4.1` 两个章节的红字保留，不转换

**4d. 手动编号重排**
- 章节删除后，段落中的手动编号（如"3.4.2"变成"3.4.1"）会断号，此步骤自动修复

**4e. 更新目录**（Word COM）
- 通过 Windows Word COM 操作文档，执行 `Repaginate` → `Update Fields` → `Update TOC`
- 由于 TCD08 模板通常是 `.docm`（带宏），更新后会检测并恢复 `vbaProject.bin` 宏保护

## 5. 执行流程

```
用户点击 Fill_TCD08
  → 前端收集 uuid/projectId/taskId/project_info/email_summary
  → POST /report/fillTCD08Report (api/report.py)
  → fetch_single_project_details(uuid)        [从 PMS Gateway 拉取项目数据]
  → apply_project_info_overrides()            [前端数据覆盖 PMS 数据]
  → 解析 Calibration Parameter (从 taskTree)
  → load generated_catalog_rules.json
  → 计算 sections_to_delete（按 Calibration Scope）
  → 计算 red_paragraph_deletions（按规则条件 + 传感器匹配）
  → 计算 red_paragraph_text_rewrites
  → _fill_docx_by_placeholders_with_optional_email_data()   [替换所有 <PMS.xxx> 和 Email.*]
  → 保存 Word 到临时目录
  → 依次执行：
      remove_empty_email_simulation_blocks()   [删除空块]
      rewrite_red_paragraph_text_batch()       [段落内局部改写]
      remove_red_paragraph_groups_batch()      [删除红色段落组]
      remove_word_sections()                   [删除章节]
      remove_template_instruction_text()       [删除提示语]
      replace_red_font_with_black()            [红字转黑字]
  → update_tocs_with_word()                    [Word COM 更新目录]
  → 将最终文件从临时目录拷贝到输出目录
  → 返回生成摘要（删除的章节、段落等统计信息）
```
