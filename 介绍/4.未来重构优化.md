# PMS 报告系统待重构 Prompt

## 一、任务背景

当前 PMS 系统已经实现多个报告功能：

- TCD08 Word 报告生成
- IAR Excel 报告生成
- Sensor Map Excel 生成
- TCD09 Word 报告生成

现有功能可以继续正常使用，本次任务的目标不是增加业务功能，而是在不改变现有行为的前提下，对后端代码进行精简、拆分、合并和规范化。

重构必须分阶段进行，禁止一次性大规模移动代码。

---

## 二、重构目标

1. 删除明确重复的函数和文件。
2. 减少 API 层中的业务逻辑。
3. 统一项目 Profile 构建流程。
4. 统一上传文件选择和映射读取逻辑。
5. 提取 TCD09 与 Sensor Map 共用的传感器解析能力。
6. 移除已经没有必要的兼容转发层。
7. 拆分 IAR、TCD08 中职责过多的大文件。
8. 统一配置文件加载与错误处理方式。
9. 统一 FastAPI 路由注册和应用入口。
10. 确保 TCD08、IAR、Sensor Map、TCD09 原有结果完全不变。

---

## 三、必须保留的现有功能

### TCD08

- 项目资料和普通占位符填写。
- Email Summary 处理。
- 根据规则删除或保留 Word 章节。
- 红字段落处理。
- 模板维护提示语处理。
- DOCM 宏保护。
- Word 目录更新。
- Calibration Parameter 和 Workflow 数据读取。
- 输出文件和压缩包生成。

### IAR

- 根据 FolderLinkMapping 选择 Excel 模板。
- 远程 PMS 和本地项目资料合并。
- Public Link 生成。
- XLSX/XLSM 占位符填写。
- 输出文件命名和下载响应。

### Sensor Map

- 传感器数量、位置、轴向和层级解析。
- 根据 JSON 规则生成最终保留项。
- Excel COM 操作。
- Excel 行和章节处理。
- 输出目录和项目名称解析。

### TCD09

- 普通 `<PMS.xxx>` 占位符填写。
- `<PMS.report_date>` 自动填写当前日期。
- Excel 章节图片提取和 Word 图片插入。
- Sensor Overview 四列表格生成。
- 传感器字符串解析。
- 汽车俯视图可编辑 Word Shape 生成。
- ECU、UFS 和外围传感器 marker 方向处理。
- Word COM 资源和临时文件正确释放。

## 四、当前已知结构问题

### 1. Profile 构建逻辑重复

IAR、TCD09 和其他报告中重复存在：

- `_to_int()`
- `_parse_project_info_json()`
- `_extract_pms_uuid_from_project_info()`
- 项目表单展开
- 空值和 `N/A` 判断
- 远程 PMS 查询
- 本地数据覆盖远程数据
- 缺失字段回退

应提取为公共项目资料模块。

### 2. 上传文件选择逻辑重复

IAR、TCD09 都在重复处理：

- 上传文件名清理
- FolderLinkMapping 读取
- TagName 查找
- FileKeyWord 匹配
- 文件扩展名校验
- 缺失文件错误

应提取为公共报告文件选择模块。

### 3. TCD09 存在重复函数

TCD09 文件选择模块中存在两个同名的 `select_tcd09_template_file()`。

必须先确认实际调用的是后定义版本，再删除重复实现，保留统一的 `_select_upload_file()` 路径。

### 4. Sensor Map 与 TCD09 重复解析传感器

两套代码都在解析：

- 传感器族
- 数量表达式
- L/R/C 等位置
- `+、_、-` 等连接符
- 默认数量
- PAS、PPS、UFS 等配置

应提取共享传感器领域层，但最终业务映射继续分开。

### 5. 兼容入口过多

当前存在只负责转发的兼容模块：

- Sensor Map 旧入口转发到新 package。
- Word 旧入口转发到拆分后的 Word package。

应先迁移所有 import，再确认无引用后删除兼容文件。

### 6. IAR API 文件职责过多

IAR API 同时负责：

- 文件选择
- Profile 构建
- Public Link
- 输出命名
- Excel 填写
- HTTP 响应

应拆分为 API、Service、Profile、Links、Excel Fill 和 Filename 模块。

### 7. TCD08 Service 职责过多

TCD08 主流程同时处理：

- 模板路径
- 输出路径
- 项目数据库
- Workflow
- Calibration Parameter
- Email Simulation
- Word 文档处理
- 输出文件

应保留一个公开生成入口，将内部职责拆到独立模块。

### 8. 配置加载方式不统一

不同功能重复实现：

- JSON 文件存在性检查
- UTF-8 BOM 读取
- JSON 解码错误
- 根节点类型校验
- 必填字段校验

应建立公共 JSON 加载器，业务 Schema 仍由各自模块校验。

### 9. FastAPI 启动入口不一致

当前多个主入口注册的路由不完全相同。

应建立统一 `create_app()` 应用工厂，只保留一个正式启动入口，确保 TCD08、IAR、Sensor Map 和 TCD09 都被注册。
